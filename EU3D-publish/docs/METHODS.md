# 方法

## 1. 工作脉络

本项目在三维反应流求解器中，逐步将对流与化学反应计算迁移到 GPU，并围绕反应计算建立多级负载平衡：

1. **CPU/MPI → CUDA/MPI**：MPI 划分计算域，每个 rank 使用一张 GPU，CUDA 执行本地对流和反应计算。
2. **跨 GPU 负载平衡**：根据格点的反应工作量，将部分反应任务从重载 rank 分配给轻载 rank，计算后返回结果。
3. **通信与计算重叠**：使用 CUDA-aware MPI 传输设备缓冲区，将本地反应与远端任务求解、结果回传衔接起来。
4. **GPU 内任务整理**：本地格点按 Nchem 分桶，迁移任务按 Nchem 排序，让同一 warp 内的线程处理工作量接近的格点。
5. **warp 动态轮转**：在分桶基础上加入共享任务队列。warp 完成一个任务块后继续领取，先完成的 warp 可以承担更多任务。

## 2. 反应工作量与调度层次

每个格点先预测反应子步数 `Nchem`，随后将当前反应时间步划分为 `Nchem` 个子步进行积分。不同格点的反应状态不同，所需子步数也不同。因此，格点数相同不一定意味着反应工作量相同。

调度使用 Nchem 作为工作量指标：单格点权重为 Nchem，rank 的估计负载为内部格点 Nchem 之和。

| 层次 | 分配对象 | 方法 |
|---|---|---|
| MPI rank / GPU 之间 | 格点反应任务 | 重载 rank 向轻载 rank 迁移任务 |
| 单 GPU 内部 | 本地格点列表 | 按 Nchem 分桶，工作量相近的格点放在一起 |
| warp 之间 | 同一桶内最多 32 个格点组成的任务块 | 从共享队列动态领取，完成后继续领取 |
| warp 内的 thread / lane | 一个格点 | 独立完成该格点的全部反应子步 |

这几层分别处理 GPU 之间的负载差异、warp 内线程的工作量差异，以及不同 warp 的完成时间差异。

## 3. 跨 rank 的动态负载平衡

MPI 保持原有计算域划分，迁移的是反应求解任务。每次重建调度计划时，先比较各 rank 的总工作量；需要平衡时，再收集格点权重生成迁移计划。

规划器反复选择当前最重和最轻的 rank。若两者负载差为 D，迁移权重为 w 的格点后，负载差变为 `|D - 2w|`，因此优先寻找接近 D/2 且能缩小差距的任务。每分配一个任务，就更新双方的预计负载，再选择下一对 rank。

成本门控通过最小任务权重和迁移数量上限控制迁移规模，减少小任务带来的打包与通信开销。计划按设定的步数间隔更新，间隔内复用任务分配。

执行过程为：

1. 将迁出格点标记到 `DLBmask`，本地反应跳过这些格点。
2. 打包 Nchem、温度、能量和组分状态，发送给目标 rank。
3. 目标 GPU 求解收到的反应任务。
4. 将温度、组分和反应源项结果传回原 rank，写回对应格点。

CUDA-aware MPI 直接使用 GPU 缓冲区。重叠路径中，收到的任务在 DLB stream 上求解，本地任务在主 stream 上计算；本地计算可与远端任务求解及结果回传重叠。后续场更新在所需结果就绪后执行。

## 4. GPU 内的 Nchem 分桶

直接按空间位置分配线程时，一个 warp 可能同时包含轻反应格点和重反应格点。轻任务先结束，重任务仍在执行，warp 内各线程的有效工作时间就会拉开。

本地反应将未迁出的格点划分为 8 个桶：

`Nchem ≤ 1`、`2–4`、`5–9`、`10–19`、`20–49`、`50–99`、`100–199`、`≥ 200`。

代码依次统计桶大小、计算起始偏移、填充格点索引列表。反应 kernel 按列表访问格点，使同一任务块中的线程处理相近的子步数。原有静态分桶版按列表位置分配任务；当前版在此基础上动态分配任务块。

分桶是否启用按重格点比例定期判断。重格点比例低于阈值时，使用普通本地反应 kernel；启用分桶时，每次本地反应重新构建任务列表。

迁移任务则在发送前按 Nchem 降序整理，由远端 kernel 中的每个线程处理一个任务。本地动态队列与远端任务列表分别执行。

## 5. warp / thread 层面的动态调度与轮转计算

动态队列以 warp 为领取单位，以 thread 为格点求解单位。每个桶维护一个共享领取指针，各 warp 从最重的桶开始取任务。

一次轮转包含以下步骤：

1. warp 的 lane 0 使用 `atomicAdd(head, 32)` 预留当前桶的一段任务。
2. 用 `__shfl_sync` 将起始位置广播给同一 warp 的其他 lane。
3. 每条有效 lane 取得一个格点，调用 `solveReactionCell`，完成该格点的全部 Nchem 子步。
4. 将结果写回，整个 warp 执行 `__syncwarp`。
5. 继续领取下一块；当前桶已无未领取任务时，转向下一个较轻的桶。所有桶都领完后退出。

这里的“轮转”是**领取一块 → 求解 → 写回并同步 → 再领取**，不是固定编号的 warp 依次执行，也不是给线程分配时间片。多个 warp 并行竞争共享队列，先完成的 warp 更早领取下一块。

例如，warp A 还在计算一块重任务，warp B 已完成自己的任务块，B 就可以继续领取剩余任务，不必等 A。当前桶的任务全部被领取后，B 还可以进入下一桶，而 A 继续完成手中的任务。

同一 warp 内，每个 thread 独立求解一个格点，但下一块任务由整个 warp 同步后一起领取。分桶缩小线程间的子步数差异，动态队列则让不同 warp 按实际完成速度分担后续工作。

每块任务最多 32 个格点，且不跨桶。尾块不足 32 个格点时，多余 lane 跳过求解，仍参与 warp 同步。原子领取保证不同 warp 获得互不重叠的任务区间。

kernel 使用每 block 256 个线程。worker block 数由 SM 数、该 kernel 的可驻留 block 数和输入规模共同确定；这些 worker 在一次 kernel 调用中循环消费任务。每次启动前将各桶领取指针清零。

## 6. 一次反应阶段的流程

1. 预测各格点 Nchem。
2. 到达重规划步时，更新跨 rank 迁移计划和本地分桶启用判断。
3. 有迁移任务时，打包并交换输入，将迁出格点从本地任务中排除。
4. 本地格点分桶后由 warp 队列轮转求解；收到的迁移任务由远端任务 kernel 求解。
5. 回传并写回迁出任务的结果。
6. 使用反应结果更新数值场，进入后续计算。

单 GPU 运行直接执行本地反应路径；多 GPU 运行在同一本地路径外增加任务迁移与结果回传。

## 7. 实验模式

| 配置 | 单 GPU | 多 GPU |
|---|---|---|
| 静态分桶对照 | `sorted` | `all` |
| 当前动态队列 | `dynamic` | `dynamic_all` |

多 GPU 两种模式均启用通信重叠、成本门控和迁移任务排序，比较的是本地静态分配与 warp 动态领取。开关由 `solver/run_intragpu_common.sh` 设置。
